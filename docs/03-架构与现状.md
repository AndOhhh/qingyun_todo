## 2. 分层与依赖方向

```
main.dart (ProviderScope)
  → routes/index.dart (onGenerateRoute + 通知跳转)
      → pages/main/index.dart (IndexedStack + 启动引导 + 跨日校准)
          ├─ pages/todo/        列表 / 编辑 / 组件
          ├─ pages/period/      列表 / 编辑 / 详情 / 周期项
          ├─ pages/schedule/    月历 / 当日安排
          ├─ pages/statistics/  指标卡 / 图表
          └─ pages/notification_guide/  诊断与厂商引导
  logic/         写操作编排：调 Repository → 按失效矩阵 invalidate → UI 反馈
  stores/        Riverpod：读 provider + 启动编排（bootstrap 还会装配通知服务）
  repositories/  业务 SQL 唯一出现处
  services/      通知 / 系统设置通道 / 厂商识别
  utils/db_helper.dart  sqflite 单例 · PRAGMA foreign_keys=ON · kSchema DDL（DDL/PRAGMA 在此）
  models/        todo · periodic · periodic_item · cycle_rule · todo_groups · 枚举 · 统计模型
  components/    跨页复用 UI（标签、表单、选择器、空/错态、浮动按钮）
```

**约定（已在代码中执行）**

- **业务 SQL（DML）只在 `repositories/`**；DDL 与 `PRAGMA` 只在 `utils/db_helper.dart`；
- `pages/` 不 import `db_helper`；**读**走 `stores/*` 的 `FutureProvider`，**写**由 `logic/*_actions.dart` 或页面直接调 Repository（三个编辑页的保存是后者）后统一走失效矩阵；
- 写操作后一律调用 `stores/invalidation.dart` 的三个封装函数，禁止零散手写 `invalidate`；**读刷新/重试**（下拉刷新、错误重试）可直接 `invalidate` 对应 provider；
- 周期日期算术集中在 `models/cycle_rule.dart` 与 `utils/date_util.dart`，**不使用** SQLite 的 `date(x,'+N month')`（月末溢出为进位而非收敛，实测 `2026-01-31 +1 month = 2026-03-03`）；
- 「当前轮」只有一个口径：`repositories/periodic_round_policy.dart`，生成引擎、待办页可见性、周期列表/详情进度共用（N21）。

### 4.6 文案

- 进度卡：`percent >= 1.0` → `今日任务全部完成 ✓`；否则 `还差 N 项任务，加油`。
- 空态：`全部搞定！` + `点击右下角的蓝色 + 按钮添加待办，\n或在「周期」页安排重复事项`。
- 删除：常规待办二次确认 + 5 秒撤销；周期实例三级动作表（只删这一次 / 删除该事项未来待办 / 删除整个周期）。
- 全部为硬编码中文，国际化列入 Phase 7（1.0 不做）。

### 7.2 实施期新发现（已修）

| 编号 | 问题 | 影响 | 处理 |
| :-- | :-- | :-- | :-- |
| **N1** | 硬删除与生成引擎幂等键冲突：实例被删后唯一键空出，下次生成会原样写回 | 删除的待办自己复活 | 新增 `periodic_skips` 墓碑表；撤销删除清墓碑；回归用例 |
| **N2** | 「完成一轮 → 生成下一轮」若沿用窗口，长周期永远等不到下一轮 | TC-08 不成立 | 拆出 `generateForPeriodicId`（后续被 N13 的一轮一期统一） |
| **N3** | `databaseFactoryFfi` 跑在独立 isolate，完成事件不是 microtask | Widget 测试停在 loading、`pumpAndSettle` 挂死 | 统一 `databaseFactoryFfiNoIsolate` + 短超时 |
| **N4** | `SwipeAction` 的 `AnimationController` 懒初始化 | dispose 时访问已 deactivated 的 element | 组件已随 N9 删除 |
| **N5** | `IndexedStack` 两个大标题导航栏共用 Hero tag | 路由切换抛 multiple heroes | 各页显式唯一 `heroTag` |
| **N6** | 无 CI | 回归靠本地 | 建议 GitHub Actions（analyze + test） |
| **N7** | `completed_count` 绝对重算，删除已完成实例会回退 | 与「已完成轮数」直觉略有出入 | 与 Q5「删除同时从分子分母消失」一致，属预期 |
| **N9** | 左滑删除的右滑方向无行为，手势语义不完整 | 用户反馈「右滑不清楚」 | 2026-10-05 整体移除滑动手势；删除走编辑页动作卡 |
| **N10** | 杀进程后收不到通知的三个根因 | 提醒丢失 | 逐条隔离失败 + 精确→非精确降级 + 通知自检横幅 + 厂商引导页 |
| **N11** | 前台兜底早期方案「到期前 90s 抢走 OS 排期」 | 前台提醒变不准、双发风险 | 已被 N13 取代 |
| **N12** | N11 方案的双发/漏发缺陷 | 一加 13 复测仍不响 | `seeding` 参数 + `_exactAlarmDenied` 硬证据（见 `computeForegroundPlan`） |
| **N13** | 前台兜底重构 | — | **OS 主通道 + 巡检只修丢单**：到期前不碰排期；到期后 60s 宽限；超宽限且排期仍在才补发收回；排期消失但本进程排期过 = OS 已送达。同时把生成引擎定为「**一轮一期**」 |
| **N14** | Q8「模板修改不追溯」导致改规则后「今天该做的事」永远生成不出来 | 用户实测：改起始日/间隔后当天仍显示旧规则那一项 | 起始日 / 间隔 / 事项天序 / 提醒时间变化 → `rebuildPending`：**已完成实例不动，未完成计划按新规则从今天所在轮重建**。UI 文案同步 |
| **N18** | 色板「跟随优先级」选项与自定义色语义重叠 | 选择成本高 | 移除「跟随」按钮；`null` = 跟随，默认高亮优先级同色色块 |
| **N19** | 「无优先级」用主色蓝，比「低」更醒目 | 视觉层级倒置 | 无/低互换：灰 → 蓝 → 橙 → 红 |
| **N20** | 编辑页完成/删除是两个不同层级的动作，且完成后还要再点保存 | 操作冗余 | 完成/删除收进同一张动作卡（绿/红 + 行首图标）；完成后直接返回上一页 |
| **N21** | 生成路径的「旧口径收敛清理」会在取消完成后删掉下一轮待办；周期列表/详情的「当前轮」与待办页不一致 | **静默丢数据**；同一周期两个「当前轮」 | 生成路径不再清理晚于本轮的实例；`_pickCurrentCycle` / `queryCurrentCycleProgress` 统一走 `PeriodicRoundPolicy` |
| **N22** | 逾期实例的「删除该事项的未来待办」只删 `remind_date >= today` | 用户点的那条删不掉，还删了别的 | 逾期实例把 `fromDate` 设为该实例日期（这一条 + 之后） |
| **N23** | 折叠箭头方向写反（收起朝上、展开朝下） | 误导 | `SectionHeader` / 日程折叠头统一为收起 ⌄ / 展开 ⌃ |
| **N24** | 通知相关：冷启动点通知不跳转；Android 通知栏图标为白块；iOS 超 64 条被丢弃 | 体验与功能缺陷 | `getNotificationAppLaunchDetails` 补跳；新增纯白 `ic_notification`；iOS 只排最近 60 条 |
| **N25** | 1.3x 字号下日历「休/班」角标压住日期数字、日程头行溢出；选择器选原值也置脏；长周期详情页堆满空白天；错误弹窗把 SQL 异常原文抛给用户 | 布局与体验 | 角标/农历小字不随字号放大；头行 `Expanded` + 省略号；选原值不置 `_dirty`；轮长 > 7 天只展示已安排事项的天 + 总入口；非校验异常只显示通用文案（原文进 `debugPrint`），`ErrorState` 仅在 debug 包展示详情 |

### 7.3 遗留注意事项

| 项 | 说明 |
| :-- | :-- |
| **统计与待办页口径差异** | 待办页按一轮一期隐藏旧轮实例，但 M4/M5/M6 仍是全库口径；统计数字可能大于可见逾期数。见 [05 §1](./05-统计指标建议.md) |
| 旧轮 pending 实例 | 不再自动清理（N21）；它们仍计入统计、日程页可见，但待办页不展示 |
| iOS 通知上限 | 系统只保留最近 64 条；已限制为最近 60 条，更远的提醒在重新打开 App 时会重新排期 |
| tyme 假日数据时效 | 覆盖至 **2026-10-10**；新一年安排公布后需升级 tyme，否则无班/休角标（农历/节气不受影响） |
| 通知的平台差异 | 国产 ROM 的「自启动 / 后台行为」需用户手动允许（引导页已覆盖）；iOS 聚焦模式需 `timeSensitive` |
| DB 迁移 | `kVersion = 1` 且 `onUpgrade` 为空：**1.0 首发后任何 schema 变更都必须升级 `kVersion` 并补迁移**，否则老用户不会执行 `onCreate` |
| Widget 测试 finder | 每日周期会在多个分组生成同名实例，断言用 `findsWidgets`；`IndexedStack` 下切 Tab 建议 `find.text('周期').last` |

## 8. 开发规范

- 遵循 `flutter_lints`；`flutter analyze` 必须零告警。
- 文件名 `snake_case`，类型名 `PascalCase`，私有成员 `_` 前缀。
- 类与公共方法用 `///` 文档注释，关键技巧加行内注释（`todo_card.dart` 的同心圆角注释是好范例）。
- 未完成的待办用 `// TODO:` 标记（当前 `lib/` 内为 0 条）。
- **文档维护约定**：涉及 `lib/` 结构、依赖、实现进度的改动，需同步更新本文 §1 / §3 / §6；表结构改动同步 [02](./02-数据库设计.md) 变更记录；行为决策在 §7.2 追加 N 编号。文档元信息统一写「核对提交 `<短 hash>` + 日期」。
