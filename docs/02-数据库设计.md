## 1. 设计原则

1. **模板与实例分离**：周期规则（"每 2 天一轮，第 1 天喝牛奶、第 2 天喝豆浆"）存为模板（`periodic_items`），每一轮真实发生的待办存为实例（`tasks`）。若混在同一张表，"列出所有待办"会同时出现模板与实例，产生重复项。
2. **时间一律用 TEXT 存储**：SQLite 无原生日期类型，统一字符串格式后可直接字典序排序、比较，并支持 `date()` / `strftime()` 运算。
3. **布尔用 INTEGER 0/1 + CHECK**：拒绝 NULL 与脏值。
4. **枚举存名字字符串**：`priority` 存 Dart 枚举 `name`（`none`/`low`/`medium`/`high`），与 `lib/models/todo.dart` 的 `TodoPriority` 对应。
5. **完成 ≠ 删除**：完成保留记录并计入统计；删除物理移除且不计入统计。周期被删除时，**已完成的实例作为历史记录保留**（见 §7.3），因此外键**不能用 CASCADE**。
6. **唯一约束保证幂等**：周期实例用 `UNIQUE(periodic_item_id, cycle_index)` 兜底，重复生成不会写出重复行；该字段被置 NULL 后不参与唯一性判定，不影响历史保留。
7. **派生值不入库**：逾期状态、周期文案等一律实时计算，避免跨天后数据陈旧。

## 2. 全局数据约定

| 项 | 约定 | 示例 |
| :-- | :-- | :-- |
| 日期 | `YYYY-MM-DD`（本地时区） | `2026-09-25` |
| 时间 | `HH:mm`（24 小时制） | `09:30` |
| 时间戳 | `YYYY-MM-DD HH:mm:ss` | `2026-09-25 09:30:00` |
| 布尔 | `INTEGER`，`0` 否 / `1` 是 | `1` |
| 颜色 | `TEXT`，`#RRGGBB` | `#FF3B30` |
| 枚举 | `TEXT`，存枚举 `name` | `high` / `MONTH` |
| `day_offset` | `INTEGER`，**0-based**，`0` = 周期第 1 天 | `1` = 周期第 2 天 |
| `cycle_index` | `INTEGER`，**0-based**，`0` = 第 1 轮 | `2` = 第 3 轮 |
| 主键 | `INTEGER PRIMARY KEY AUTOINCREMENT` | — |
| 命名 | 表名复数 snake_case；时间戳统一 `created_at` / `updated_at` | — |

## 3. ER 关系

```
periodic_configs (1) ──< (N) periodic_items     周期 → 周期内的模板项      [CASCADE]
periodic_configs (1) ──< (N) tasks              周期 → 已生成的实例        [SET NULL]
periodic_items   (1) ──< (N) tasks              模板项 → 各轮次实例        [SET NULL]
periodic_items   (1) ──< (N) periodic_skips     模板项 → 删除墓碑          [CASCADE]

常规待办：tasks.periodic_id IS NULL 且 source_type = 'REGULAR'
周期实例：source_type = 'PERIODIC'
  ├─ periodic_id NOT NULL → 来源周期仍存在
  └─ periodic_id IS NULL  → 来源周期已被删除（历史保留记录，靠 periodic_name_snapshot 显示来源）
```

> `periodic_skips` 只被生成引擎读取（判断"用户删过的这一轮不要再生成"），不参与统计与展示。

**为什么 `tasks` 用 SET NULL 而不是 CASCADE**：评审决策要求"删除周期时保留之前已完成的周期待办记录"。CASCADE 会连带删掉已完成的历史记录，导致统计失真，故改为 SET NULL + 应用层条件删除（§7.3）。

## 4. 表结构

### 4.1 `periodic_configs`（周期配置表）

| 字段名 | 类型 | 约束 | 说明 |
| :-- | :-- | :-- | :-- |
| `id` | INTEGER | PK AUTOINCREMENT | 周期 ID |
| `name` | TEXT | NOT NULL | 周期名称，如"隔天喝饮品计划" |
| `start_date` | TEXT | NOT NULL | 起始日期 `YYYY-MM-DD`，视为第 1 轮第 1 天。MONTH/YEAR 类型下同时锚定"每月/每年的第几号" |
| `interval_type` | TEXT | NOT NULL DEFAULT 'DAY', CHECK(IN DAY/WEEK/MONTH/YEAR) | 周期单位 **【v2.1 新增】** |
| `interval_value` | INTEGER | NOT NULL DEFAULT 1, CHECK(> 0) | 周期数量：每 `interval_value` 个 `interval_type` 一轮 **【v2.1 新增】** |
| `completed_count` | INTEGER | NOT NULL DEFAULT 0, CHECK(>= 0) | 已完结的轮数（有意冗余，便于统计页快速读取） |
| `is_active` | INTEGER | NOT NULL DEFAULT 1, CHECK(IN 0,1) | 是否启用；`0`=暂停，暂停后停止生成新实例 |
| `end_date` | TEXT | 可空 | 周期终止日期（含）；`NULL` = 无限循环 |
| `remark` | TEXT | 可空 | 备注 |
| `created_at` | TEXT | NOT NULL | 创建时间 |
| `updated_at` | TEXT | NOT NULL | 最后更新时间 |

**预设组合**（周期新增页快捷选项，对应 **Q14 已决策**）：

| UI 文案 | `interval_type` | `interval_value` | 一轮天数 |
| :-- | :-- | --: | :-- |
| 每天 | DAY | 1 | 1（固定） |
| 每 2 天 | DAY | 2 | 2（固定） |
| 自定义天数 | DAY | N | N（固定） |
| 每周 | WEEK | 1 | 7（固定） |
| 每 2 周 | WEEK | 2 | 14（固定） |
| 每月 | MONTH | 1 | 28–31（**按自然月**） |
| 每年 | YEAR | 1 | 365–366（**按自然年**） |

> 为什么不用"每月 = 30 天"近似：3 个月就会漂移 1–2 天，"每月 1 号交房租"这类真实场景会跑到 2 号、3 号。因此 MONTH/YEAR 走日历算术（§7.1），DAY/WEEK 走天数算术。

### 4.2 `periodic_items`（周期项 / 模板表）

| 字段名 | 类型 | 约束 | 说明 |
| :-- | :-- | :-- | :-- |
| `id` | INTEGER | PK AUTOINCREMENT | 周期项 ID |
| `periodic_id` | INTEGER | NOT NULL, FK → `periodic_configs(id)` **ON DELETE CASCADE** | 所属周期（模板随周期一起删，无保留需求） |
| `day_offset` | INTEGER | NOT NULL DEFAULT 0, CHECK(>= 0) | 周期内天序，0-based。上限见 §7.2（跨表约束，应用层校验） |
| `title` | TEXT | NOT NULL | 待办标题，如"喝牛奶" |
| `remark` | TEXT | 可空 | 备注 |
| `remind_time` | TEXT | 可空 | 提醒时间点 `HH:mm`。**周期本身不带提醒时间，时间挂在项上** |
| `priority` | TEXT | NOT NULL DEFAULT 'none', CHECK(IN none/low/medium/high) | 优先级 |
| `accent_color` | TEXT | 可空 | 卡片色带颜色 `#RRGGBB`；`NULL` 时由 `priority` 推导 |
| `sort_order` | INTEGER | NOT NULL DEFAULT 0 | 同一天内多项时的展示顺序 |
| `created_at` | TEXT | NOT NULL | 创建时间 |
| `updated_at` | TEXT | NOT NULL | 更新时间 |

### 4.3 `tasks`（待办任务表：常规待办 + 周期实例）

| 字段名 | 类型 | 约束 | 说明 |
| :-- | :-- | :-- | :-- |
| `id` | INTEGER | PK AUTOINCREMENT | 任务 ID。Dart 侧 `Todo.id` 为 `int?`（新建时 null，落库后回填） |
| `title` | TEXT | NOT NULL | 标题。周期实例生成时从 `periodic_items.title` 拷贝，之后可单独修改 |
| `remark` | TEXT | 可空 | 备注 |
| `remind_date` | TEXT | NOT NULL | 提醒日期 `YYYY-MM-DD`。常规任务由用户指定；周期实例由规则推算 |
| `remind_time` | TEXT | 可空 | 提醒时间点 `HH:mm`，周期实例可独立覆盖模板值 |
| `priority` | TEXT | NOT NULL DEFAULT 'none', CHECK(IN none/low/medium/high) | 优先级枚举名 |
| `accent_color` | TEXT | 可空 | 卡片色带颜色 `#RRGGBB` |
| `is_completed` | INTEGER | NOT NULL DEFAULT 0, CHECK(IN 0,1) | 完成状态。**完成后记录永久保留，删除才会移除** |
| `completed_at` | TEXT | 可空 | 完成时间；取消完成时置回 `NULL`。统计页趋势与时长依赖此字段 |
| `source_type` | TEXT | NOT NULL DEFAULT 'REGULAR', CHECK(IN REGULAR/PERIODIC) | `REGULAR` 常规 / `PERIODIC` 周期实例（**即使来源周期已删也保持 PERIODIC**） |
| `periodic_id` | INTEGER | 可空, FK → `periodic_configs(id)` **ON DELETE SET NULL** | 常规待办为 `NULL`；周期被删后自动置 `NULL` |
| `periodic_item_id` | INTEGER | 可空, FK → `periodic_items(id)` **ON DELETE SET NULL** | 来源模板项，幂等键之一 |
| `cycle_index` | INTEGER | 可空, CHECK(>= 0) | 第几轮，0-based。**来源周期删除后仍保留**，用于展示"第 N 轮" |
| `periodic_name_snapshot` | TEXT | 可空 | **【v2.1 新增】** 生成实例时写入周期名称快照。来源周期被删除后，UI 仍能显示"周期·xxx" |
| `sort_order` | INTEGER | NOT NULL DEFAULT 0 | 手动排序（支撑后续拖拽） |
| `is_notified` | INTEGER | NOT NULL DEFAULT 0, CHECK(IN 0,1) | 提醒是否已发出，防重复通知 |
| `created_at` | TEXT | NOT NULL | 创建时间 |
| `updated_at` | TEXT | NOT NULL | 更新时间 |

> **逾期不是字段**：一律由 `remind_date < today AND is_completed = 0` 实时派生（`Todo.isOverdue` getter）。
> **孤儿实例判定**：`source_type = 'PERIODIC' AND periodic_id IS NULL` → 来源周期已删除；仍计入历史统计，
> **可以取消完成或删除**（走常规删除确认），只是不提供跳回周期的入口。

### 4.4 `periodic_skips`（周期实例删除墓碑表）**【v2.2 新增】**

| 字段名 | 类型 | 约束 | 说明 |
| :-- | :-- | :-- | :-- |
| `periodic_item_id` | INTEGER | PK 之一, NOT NULL, FK → `periodic_items(id)` **ON DELETE CASCADE** | 被删除实例的来源模板项 |
| `cycle_index` | INTEGER | PK 之一, NOT NULL | 轮次，0-based |
| `reason` | TEXT | NOT NULL DEFAULT 'USER_DELETED' | `USER_DELETED` 删这一次 / `FUTURE_DELETED` 删未来实例 |
| `created_at` | TEXT | NOT NULL | 记录时间 |

**为什么需要它**：生成引擎的幂等键是 `UNIQUE(periodic_item_id, cycle_index)`。
待办是**硬删除**（Q5），实例行被删掉后这个键就空出来了 —— 下一次窗口生成
（App 启动 / 跨日校准 / 新建周期项）会把用户刚删掉的待办**原样写回来**。
墓碑表记录「用户主动删除过的 (周期项, 轮次) 组合」，生成时跳过（见 [04 §5](./04-数据层与CRUD.md)）。

| 规则 | 说明 |
| :-- | :-- |
| 写入时机 | `TaskRepository.deleteById` / `deleteByIds`（周期实例）、`PeriodicItemRepository.deleteFutureInstances` |
| 清除时机 | `TaskRepository.restore`（5 秒撤销）→ 该实例重新受生成规则管辖 |
| 自动回收 | 周期项被删除时 `ON DELETE CASCADE` 清理；删除周期 → 周期项级联 → 墓碑一并清理，不会无限增长 |
| 不参与统计 | 仅生成引擎读取，任何统计口径都不涉及本表 |

### 4.5 已移除：`subtasks`（子任务表）

v2 曾设计 `subtasks` 表支撑卡片上的 `x/y` 进度标签。**2026-09-25 评审决策：待办任务每条都是独立任务，移除子任务功能**（**Q2 已决策**）。因此 v2.1 不建此表，相关代码（`Todo.subDone/subTotal`、`todo_card.dart` 的 `x/y` 标签、mock 数据）需一并清理，见 [03 §7 R11](./03-架构与现状.md)。若未来需要，DDL 见文末附录。

## 5. 完整 DDL

> 已在 `sqlite3 3.50.6` 实测通过：建表、索引、CHECK、`SET NULL` 与 `CASCADE` 混合行为、"删周期保留已完成实例"全流程均验证（§7.3）。
> 执行前需 `PRAGMA foreign_keys = ON;`（SQLite 默认关闭外键，`sqflite` 中在 `onConfigure` 里设置，否则 SET NULL / CASCADE 全部失效）。

```sql
PRAGMA foreign_keys = ON;

-- ============ 表1：周期配置表 ============
CREATE TABLE IF NOT EXISTS periodic_configs (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    name            TEXT    NOT NULL,
    start_date      TEXT    NOT NULL,
    interval_type   TEXT    NOT NULL DEFAULT 'DAY'
                    CHECK (interval_type IN ('DAY', 'WEEK', 'MONTH', 'YEAR')),
    interval_value  INTEGER NOT NULL DEFAULT 1 CHECK (interval_value > 0),
    completed_count INTEGER NOT NULL DEFAULT 0 CHECK (completed_count >= 0),
    is_active       INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0, 1)),
    end_date        TEXT,
    remark          TEXT,
    created_at      TEXT    NOT NULL,
    updated_at      TEXT    NOT NULL
);

-- ============ 表2：周期项（模板）表 ============
CREATE TABLE IF NOT EXISTS periodic_items (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    periodic_id  INTEGER NOT NULL,
    day_offset   INTEGER NOT NULL DEFAULT 0 CHECK (day_offset >= 0),
    title        TEXT    NOT NULL,
    remark       TEXT,
    remind_time  TEXT,
    priority     TEXT    NOT NULL DEFAULT 'none'
                 CHECK (priority IN ('none', 'low', 'medium', 'high')),
    accent_color TEXT,
    sort_order   INTEGER NOT NULL DEFAULT 0,
    created_at   TEXT    NOT NULL,
    updated_at   TEXT    NOT NULL,
    FOREIGN KEY (periodic_id) REFERENCES periodic_configs (id) ON DELETE CASCADE
);

-- ============ 表3：待办任务表（常规 + 周期实例 + 历史保留记录） ============
CREATE TABLE IF NOT EXISTS tasks (
    id                     INTEGER PRIMARY KEY AUTOINCREMENT,
    title                  TEXT    NOT NULL,
    remark                 TEXT,
    remind_date            TEXT    NOT NULL,
    remind_time            TEXT,
    priority               TEXT    NOT NULL DEFAULT 'none'
                           CHECK (priority IN ('none', 'low', 'medium', 'high')),
    accent_color           TEXT,
    is_completed           INTEGER NOT NULL DEFAULT 0 CHECK (is_completed IN (0, 1)),
    completed_at           TEXT,
    source_type            TEXT    NOT NULL DEFAULT 'REGULAR'
                           CHECK (source_type IN ('REGULAR', 'PERIODIC')),
    periodic_id            INTEGER,
    periodic_item_id       INTEGER,
    cycle_index            INTEGER CHECK (cycle_index IS NULL OR cycle_index >= 0),
    periodic_name_snapshot TEXT,
    sort_order             INTEGER NOT NULL DEFAULT 0,
    is_notified            INTEGER NOT NULL DEFAULT 0 CHECK (is_notified IN (0, 1)),
    created_at             TEXT    NOT NULL,
    updated_at             TEXT    NOT NULL,
    FOREIGN KEY (periodic_id)      REFERENCES periodic_configs (id) ON DELETE SET NULL,
    FOREIGN KEY (periodic_item_id) REFERENCES periodic_items (id)   ON DELETE SET NULL
);

-- ============ 表4：周期实例删除墓碑表（v2.2） ============
-- 硬删除后 UNIQUE(periodic_item_id, cycle_index) 会空出来，
-- 若不记录，下一次窗口生成会把用户刚删掉的待办原样写回
CREATE TABLE IF NOT EXISTS periodic_skips (
    periodic_item_id INTEGER NOT NULL,
    cycle_index      INTEGER NOT NULL,
    reason           TEXT    NOT NULL DEFAULT 'USER_DELETED',
    created_at       TEXT    NOT NULL,
    PRIMARY KEY (periodic_item_id, cycle_index),
    FOREIGN KEY (periodic_item_id) REFERENCES periodic_items (id) ON DELETE CASCADE
);

-- ============ 索引（7 条） ============
CREATE INDEX IF NOT EXISTS idx_tasks_remind_date    ON tasks (remind_date);
CREATE INDEX IF NOT EXISTS idx_tasks_pending        ON tasks (is_completed, remind_date);
CREATE INDEX IF NOT EXISTS idx_tasks_periodic       ON tasks (periodic_id);
CREATE INDEX IF NOT EXISTS idx_tasks_source_type    ON tasks (source_type);
CREATE INDEX IF NOT EXISTS idx_tasks_completed_at   ON tasks (completed_at);
CREATE INDEX IF NOT EXISTS idx_periodic_items_group ON periodic_items (periodic_id, day_offset);

-- 幂等键：同一模板项在同一轮次只能有一个实例。
-- 常规待办与历史保留记录的 periodic_item_id 为 NULL，SQLite 中 NULL 互不相等，故不受影响。
CREATE UNIQUE INDEX IF NOT EXISTS idx_tasks_instance_unique
    ON tasks (periodic_item_id, cycle_index);
```

## 7. 周期规则

### 7.1 轮次起始日与轮次长度

```
cycleStart(k)：                                     // k = 0,1,2,…
  DAY   → start_date + k × interval_value 天
  WEEK  → start_date + k × interval_value × 7 天
  MONTH → start_date 加 (k × interval_value) 个月，日号锚定；
          目标月无该日号时取该月最后一天（如 1/31 → 2/28）
  YEAR  → start_date 加 (k × interval_value) 年，同上（2/29 → 2/28）

cycleLength(k) = cycleStart(k+1) − cycleStart(k) 的天数
  DAY   → interval_value          （固定）
  WEEK  → interval_value × 7      （固定）
  MONTH → 28 ~ 31                 （随月份变化）
  YEAR  → 365 ~ 366               （随闰年变化）

实例提醒日期 = cycleStart(k) + item.day_offset 天
```

> ⚠️ **实现陷阱（已实测）**：MONTH/YEAR 的日历算术**必须在 Dart 层实现，不能用 SQLite 的 `date(x, '+N month')`**。
> SQLite 对月末溢出做的是"进位"而不是"收敛"：`date('2026-01-31','+1 month')` = `2026-03-03`（而非 2/28），`date('2024-02-29','+1 year')` = `2025-03-01`。
> Dart 侧需自行判断"目标月是否存在该日号"，不存在则取该月最后一天。DAY/WEEK 类型无此问题，可直接用天数加法。

### 7.2 `day_offset` 约束与跳过规则

| 场景 | 规则 |
| :-- | :-- |
| 保存校验（周期项新增/编辑） | `0 <= day_offset < minCycleLength`，其中 DAY/WEEK 取精确长度，**MONTH 取 28，YEAR 取 365**（按最短轮次校验，避免 2 月/平年失效） |
| 生成时 | 若 `day_offset >= cycleLength(k)`，该轮**跳过该项**。⚠️ 由于上一条的上限恒小于最短轮长度，**UI 可达数据不会触发该分支**；它只对直接写库的历史/测试数据生效 |
| ~~UI 提示~~ | 旧版「MONTH/YEAR 且 `day_offset >= 28` 提示短月份跳过」的横幅已移除（提示永远不成立） |
| 缩小周期（**Q12 已决策**） | 修改 `interval_type`/`interval_value` 使已有周期项越界时，**阻止保存**并列出冲突项，要求用户先调整 |

> 实际可选范围：MONTH 第 1~28 天、YEAR 第 1~365 天、DAY N 第 1~N 天、WEEK N 第 1~7N 天。

### 7.3 删除语义（**Q5 / Q9 已决策**）

| 操作 | 数据处理 | 统计影响 | UI |
| :-- | :-- | :-- | :-- |
| **标记完成** | `is_completed=1` + `completed_at=now`，记录保留 | 计入分母与分子 | 可逆，再点取消（`completed_at` 置 NULL） |
| **取消完成** | `is_completed=0` + `completed_at=NULL`；若为周期实例，回退所属周期 `completed_count`（**Q13**） | 从分子移出 | — |
| **删除单条待办** | 物理删除该行（无论是否已完成） | **从分母与分子同时消失** | 二次确认 + 5 秒撤销 |
| **删除周期项** | 事务内：① 删该项**未完成**实例 ② 删模板行；该项**已完成**实例保留，`periodic_item_id` 自动置 NULL | 已完成记录继续计入历史统计 | 确认文案说明"将删除 N 条未完成待办，已完成的 M 条保留为历史" |
| **删除周期** | 事务内：① 删该周期**未完成**实例 ② 删 `periodic_configs` 行 → `periodic_items` 级联删除 → 剩余**已完成**实例的 `periodic_id`/`periodic_item_id` 自动置 NULL，`cycle_index` 与 `periodic_name_snapshot` 保留 | 已完成记录继续计入历史统计 | 同上；优先引导"暂停" |

**删除周期的 SQL（事务内按序执行）**：

```sql
-- ① 未完成实例物理删除
DELETE FROM tasks WHERE periodic_id = :id AND is_completed = 0;
-- ② 删除周期本体：periodic_items 级联删除；
--    剩余已完成实例的 periodic_id / periodic_item_id 由 ON DELETE SET NULL 自动置空
DELETE FROM periodic_configs WHERE id = :id;
```

**孤儿历史记录的识别与展示**：

```sql
SELECT * FROM tasks
WHERE source_type = 'PERIODIC' AND periodic_id IS NULL
ORDER BY remind_date DESC;
```

UI 表现：保留原 `periodic_name_snapshot` 与 `第 N 轮` 信息，标签显示为"周期·{快照名}"，不提供"跳转到周期"入口（来源已不存在），可正常取消完成或删除。

### 7.4 生成与完结

```
生成前置条件：is_active = 1 且 (end_date IS NULL OR remind_date <= end_date)
预生成口径  ：一轮一期（N13）—— 每个周期只保「本轮」实例
              （当前轮 = 最早的未完成轮；该轮整轮走完 → 顺延到「今天所在轮」；
               全部完结 / 无实例 → max(今天所在轮, 已有最大轮次 + 1)）
幂等保证    ：INSERT … ON CONFLICT(periodic_item_id, cycle_index) DO NOTHING
历史实例    ：默认不补生成（Q1 默认）
轮次完结    ：第 k 轮满足 COUNT(*) WHERE periodic_id=? AND cycle_index=k AND is_completed=0 = 0
              → CycleCounter.sync 绝对重算 completed_count → 对齐下一轮生成
              （被手动删除的实例不再计入判定，即"删掉唯一未完成项"也算完结）
```

> `completed_count` 不是 `±1` 增减，而是「有 ≥1 条实例、且没有未完成实例」的轮次数重算
> （幂等；同时满足取消完成回退、删除唯一未完成项完结）。见 `repositories/cycle_counter.dart`。

**示例 1**：`start_date = 2026-09-25`，DAY/2；项 A `day_offset=0` 喝牛奶 09:00，项 B `day_offset=1` 喝豆浆 09:00。
（一轮一期：实际只会生成「当前轮」两条，完成后才生成下一轮。）

| `cycle_index` | 轮起始日 | 生成实例 |
| :-- | :-- | :-- |
| 0 | 2026-09-25 | 09-25 09:00 喝牛奶　/　09-26 09:00 喝豆浆 |
| 1 | 2026-09-27 | 09-27 09:00 喝牛奶　/　09-28 09:00 喝豆浆 |
| 2 | 2026-09-29 | 09-29 09:00 喝牛奶　/　09-30 09:00 喝豆浆 |

**示例 2**：`start_date = 2026-09-01`，MONTH/1（每月）；项 A `day_offset=0` 交房租，项 B `day_offset=27` 月末盘点。

| `cycle_index` | 轮起始日 | 轮长度 | 生成实例 |
| :-- | :-- | --: | :-- |
| 0 | 2026-09-01 | 30 | 09-01 交房租　/　09-28 月末盘点 |
| 1 | 2026-10-01 | 31 | 10-01 交房租　/　10-28 月末盘点 |
| 5 | 2027-02-01 | 28 | 02-01 交房租　/　02-28 月末盘点（`27 < 28`，正常生成） |

> 旧版示例用 `day_offset=28` 演示「2 月跳过」，该值在 Q12 定案后不可保存（见 §7.2）；
> 跳过分支现在只作为防御逻辑，由单测直接写库覆盖。

**规则/日期被修改时的处理（N14，取代原 Q8）**

- 修改 `start_date` / `interval_*`，或修改周期项的 `day_offset` / `remind_time` 后：
  - **已完成实例**保持原日期不动（历史真实）；
  - **未完成计划**按新规则从「今天所在轮」重建（`PeriodicGenerator.rebuildPending`，同事务）；
  - `completed_count` 不重置。
- 仅改标题 / 备注 / 优先级 / 色带时，已生成实例完全不变（不追溯）。
- 原因：若未完成计划也保持旧日期，改过起始日/间隔后「本轮」会被钉在旧编号上，
  新规则算出的「今天该做的事」永远生成不出来（实测问题）。

## 8. 典型查询 SQL

```sql
-- 8.1 待办页候选集（逾期 / 今天 / 明天 / 后续 / 已完成）
--     实际实现：先取全量，再在 Dart 侧用 PeriodicRoundPolicy 过滤「非本轮」的未完成周期实例，
--     然后按日期分桶；「已完成」组在 Dart 侧按 completed_at DESC 重排。
SELECT * FROM tasks
ORDER BY is_completed ASC, remind_date ASC,
         CASE WHEN remind_time IS NULL THEN 1 ELSE 0 END,
         remind_time ASC, sort_order ASC;

-- 8.2 日程页：指定日期的全部待办（remind_time 为 NULL 的「全天」排最后）
SELECT * FROM tasks WHERE remind_date = :date
ORDER BY CASE WHEN remind_time IS NULL THEN 1 ELSE 0 END, remind_time, sort_order;

-- 8.3 今日进度（仅统计 remind_date = 今天，含周期实例）
SELECT COUNT(*) AS total, COALESCE(SUM(is_completed), 0) AS done
FROM tasks WHERE remind_date = :today;

-- 8.4 逾期任务（全库口径，含待办页隐藏的旧轮实例）
SELECT * FROM tasks
WHERE is_completed = 0 AND remind_date < :today
ORDER BY remind_date ASC;

-- 8.5 某周期下的全部实例（周期详情页）
SELECT * FROM tasks WHERE periodic_id = :periodicId
ORDER BY remind_date ASC, remind_time ASC;

-- 8.6 判断第 k 轮是否已无未完成实例（用于 CycleCounter.sync）
SELECT COUNT(*) AS unfinished FROM tasks
WHERE periodic_id = :periodicId AND cycle_index = :k AND is_completed = 0;

-- 8.7 周期本轮进度 x/y（:currentCycle 由 PeriodicRoundPolicy 计算，与生成引擎同源）
SELECT cycle_index,
       COUNT(*) AS total,
       COALESCE(SUM(is_completed), 0) AS done
FROM tasks
WHERE periodic_id = :periodicId AND cycle_index = :currentCycle
GROUP BY cycle_index;

-- 8.8 下次提醒（周期卡片副标题，只取本轮实例）
SELECT remind_date, remind_time, title FROM tasks
WHERE periodic_id = :periodicId AND is_completed = 0
  AND cycle_index = :currentCycle
  AND remind_date >= :today
ORDER BY remind_date, CASE WHEN remind_time IS NULL THEN 1 ELSE 0 END,
         remind_time LIMIT 1;

-- 8.9 孤儿历史记录（来源周期已删除）
SELECT * FROM tasks WHERE source_type = 'PERIODIC' AND periodic_id IS NULL
ORDER BY remind_date DESC;
```

> §8 的 SQL 为**示意**（可直接在 sqlite3 跑通）；实际查询见 `lib/repositories/*.dart`，
> 其中 8.1 的「一轮一期」过滤、8.7/8.8 的「当前轮」都在 Dart 侧完成。
