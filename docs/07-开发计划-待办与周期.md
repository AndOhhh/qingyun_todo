### A.1 Riverpod 落地约定（Q7 已定案）

**依赖**：`flutter_riverpod`（版本以 `flutter pub add` 为准）。**不引入** `riverpod_generator` / `build_runner`——provider 数量约 24 个，手写更直观，避免代码生成拖慢构建与调试。

**启动接线（实际写法）**：

```dart
// lib/main.dart
void main() {
  WidgetsFlutterBinding.ensureInitialized();
  runApp(ProviderScope(child: getRootWidget()));
}

// lib/pages/main/index.dart → initState
WidgetsBinding.instance.addPostFrameCallback((_) {
  if (mounted) bootstrapApp(ref);   // 建库 + 生成本轮实例 + 初始化通知
});
```

> 原计划的「`main()` 里 `await databaseProvider.future` + `overrideWithValue`」**未采用**：
> 建库与首次生成放在 `bootstrapApp`（`lib/stores/bootstrap.dart`），不阻塞首帧；
> 失败只记录日志，幂等保证下次触发可重试。

**Provider 分类与命名**：

| 类型 | 命名 | 用途 | 示例 |
| :-- | :-- | :-- | :-- |
| `Provider<T>` | `xxxRepositoryProvider` | 同步创建单例依赖 | `taskRepositoryProvider` |
| `FutureProvider<T>` | `xxxProvider` / `xxxListProvider` | 读数据，自带 loading/error/data 三态 | `todoGroupsProvider` |
| `FutureProvider.family<T, Arg>` | `xxxProvider` | 带参数读取 | `periodicDetailProvider(id)` |
| —（不建写 provider） | — | 写操作直接 `ref.read(repo).method()`，完成后 `ref.invalidate(相关读 provider)` | — |

**store 文件职责**：

| 文件 | 内容 |
| :-- | :-- |
| `lib/stores/db_providers.dart` | `databaseProvider` + 4 个 repository provider |
| `lib/stores/todo_store.dart` | `todoGroupsProvider`、`todayProgressProvider`、`todoDetailProvider(id)` |
| `lib/stores/periodic_store.dart` | `periodicListProvider`、`periodicDetailProvider(id)`、`cyclePreviewProvider(rule)`（C2-5 预览复用同一套 `CycleRule`） |

**失效矩阵（以实现为准）**：`lib/stores/invalidation.dart` 提供三个封装函数：

| 函数 | 失效的 provider |
| :-- | :-- |
| `invalidateAfterTaskWrite(invalidate, {periodicId})` | `todoGroups`、`todayProgress`、`todoDetail`、`monthMarkers`、`dayTasks`、`statsSummary`、`statsCharts`、`statsHeatmap`；周期实例额外 `periodicList`、`periodicDetail(id)`、`periodicInstances(id)` |
| `invalidateAfterPeriodicWrite(invalidate)` | 周期列表/详情/周期项/实例计数、`monthMarkers`、`dayTasks`、统计三件套、待办三件套 |
| `invalidateAfterGenerate(invalidate)` | `todoGroups`、`todayProgress`、`periodicInstances`、`periodicList`、`monthMarkers`、`dayTasks`、统计三件套 |

> 写操作**必须**走这三个函数；**读刷新/错误重试**（下拉刷新、`ErrorState.onRetry`）可以直接
> `invalidate` 对应 provider，不算违反约定。

**全局状态 vs UI 局部状态的边界**：

| 数据 | 归属 | 理由 |
| :-- | :-- | :-- |
| 待办分组、今日进度、周期列表/详情 | provider | 跨页共享、来源于 DB |
| 已完成分组是否折叠（`_showCompleted`） | Widget 内 `setState` | 纯 UI 偏好；B1-6 若做持久化再提升 |
| 表单草稿值 | `TextEditingController` | 未提交的数据不属于全局状态 |
| 当前选中 Tab（`_currentIndex`） | `MainPage` 内 `setState` | 保持现状，无需改造 |

→ 页面基类：无本地状态用 `ConsumerWidget`；有 UI 局部状态（折叠、滚动位置、表单）用 `ConsumerStatefulWidget` + `setState`。**不要为了"统一"把折叠状态也塞进 provider**。

**加载 / 错误 / 空态**：统一 `AsyncValue.when(loading:, error:, data:)`；`error` 分支复用 `lib/components/error_state.dart`（含重试按钮，重试即 `ref.invalidate` 对应 provider），对应任务 B1-4。

**乐观更新**：M2 先用"写库 → `invalidate` → 重取"的朴素方案（本地 SQLite 写入通常 < 10ms，用户无感）。若 M3 实测勾选有明显迟滞，再对 `toggleComplete` 单点引入乐观更新（手动 patch `AsyncValue.data`，失败回滚 + 提示）。**不要一上来就全局乐观更新**，它与失效矩阵叠加会产生难查的状态错乱。

**测试约定**：
- 数据层：`sqflite_common_ffi` 真库直测 Repository（不经 provider）。
- Provider 逻辑：`ProviderContainer(overrides: [...])` + `await container.read(todoGroupsProvider.future)`，无需 pump widget。
- Widget：`ProviderScope(overrides: [taskRepositoryProvider.overrideWithValue(FakeTaskRepository())], child: ...)`。
- 失效矩阵需有断言覆盖（如"完成周期实例后 `periodicListProvider` 取到新的 `completed_count`"），对应 TC-08 / TC-09。

## G. 风险与注意事项

| 风险 | 说明 | 应对 |
| :-- | :-- | :-- |
| **外键未开启** | `sqflite` 默认不启用外键，漏写 `PRAGMA foreign_keys = ON` 会让 SET NULL / CASCADE 静默失效，删除周期后留下悬挂外键 | `DbHelper.onConfigure` 中开启，并在测试中断言（TC-11 依赖此行为） |
| **SQLite 月份加法溢出** | `date(x,'+N month')` 是进位而非收敛（`2026-01-31 +1 month = 2026-03-03`） | 全部日历算术在 Dart `CycleRule` 中实现并单测（TC-02/03） |
| 唯一索引与历史保留冲突 | 已完成实例被置 NULL 后不再占用 `(periodic_item_id, cycle_index)` 唯一键 | 已实测：置 NULL 后可正常插入新记录，不会误判重复 |
| 撤销删除的实现 | 硬删除无法靠数据库回滚 | `deleteById` 返回整行快照 + `insertWithId` 显式写回原 id |
| 生成引擎重复触发 | 4 个触发时机可能并发 | 幂等键兜底 + store 层串行化生成调用 |
| **invalidate 漏写** | 写操作后忘记失效对应 provider → 页面显示旧数据，是 Riverpod 项目最高频 bug | 按 §A.1 失效矩阵封装为统一函数，禁止零散手写；测试中断言（TC-08/09） |
| 全局状态过度膨胀 | 把折叠、表单草稿、当前 Tab 等 UI 局部状态也塞进 provider | 遵守 §A.1 边界表，纯 UI 状态留在 Widget |
| 范围蔓延 | 搜索/筛选/拖拽/通知容易被顺手加进来 | 一律按 §B7 与 [06](./06-路线图.md) 延后，不进本计划 |
