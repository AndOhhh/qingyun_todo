## 1. 统一口径（先定口径，再定指标）

| 口径项 | 约定 | 说明 |
| :-- | :-- | :-- |
| "今天" | `DateUtil.today()`（本地时区） | 全按本地时区；DB 存 `YYYY-MM-DD` / `YYYY-MM-DD HH:mm:ss`，禁止 UTC |
| 完成率归属 | 按 **`remind_date`** | "9/25 的完成率" = 提醒日为 9/25 的任务中已完成的比例 |
| 完成趋势归属 | 按 **`completed_at`** | "9/25 完成了几个" = 实际完成动作发生在 9/25 |
| 逾期 | `is_completed = 0 AND remind_date < today` | 实时派生，不入库 |
| 周期任务 | `source_type = 'PERIODIC'` | **M1/M2 计入全部任务（含周期实例）；M6 单列周期口径**（D3） |
| 空数据 | 分母为 0 时展示 `--` 而非 `0%` | 避免新用户看到"完成率 0%"的挫败感 |
| 硬删除记录 | **不计入**任何分母与分子 | 物理移除；这是"删除"与"完成"的本质区别（Q5） |
| 孤儿周期记录 | **计入**周期完成率与历史统计 | 来源周期已删除但已完成实例保留；判定依据是 `source_type = 'PERIODIC'` 而非 `periodic_id` |

> ⚠️ 完成率与完成趋势分属两套口径（`remind_date` vs `completed_at`），混用会导致"完成率 100% 但趋势图为 0"的矛盾。UI 上分别标注"应完成"与"实际完成"。

> ℹ️ **已知口径差异（1.0 保留，待后续统一）**：待办页按「一轮一期」只展示当前轮，但 M4 逾期 / M5 待处理 / M6 周期完成率仍是**全库口径**，会把「错过的旧轮未完成实例」算进去。表现为统计数字可能大于待办页可见的逾期数。若要统一，需要把 `PeriodicRoundPolicy` 引入统计查询（见 `README.md` 的 Roadmap）。

## 2. 首屏指标（M1~M6，固定口径，不受范围切换影响）

| # | 指标 | 定义 | 计算口径 | 展示形式 | 依赖字段 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| M1 | 今日完成率 | 今日应完成任务中已完成的占比 | `SUM(is_completed)/COUNT(*) WHERE remind_date = today` | 环形 + 大数字 % | `remind_date`,`is_completed` |
| M2 | 本周完成率 | 本周（周一起算）应完成任务的完成占比 | 同上，`remind_date BETWEEN 周一 AND 周日` | % + 7 格点阵 | 同上 |
| M3 | 连续打卡天数 | 从今天向前回溯、每天都有 ≥1 条完成记录的连续天数（今天未完成时从昨天起算，不断链） | `substr(completed_at,1,10)` 去重后回溯 | 火焰 + N 天 + 里程碑进度 | `completed_at` |
| M4 | 逾期任务数 | 未完成且提醒日早于今天 | `COUNT(*) WHERE is_completed=0 AND remind_date<today` | **状态化配色**：0 → 绿色「没有逾期任务」；>0 → 红色 | `remind_date` |
| M5 | 待处理总数 | 全部未完成待办 | `COUNT(*) WHERE is_completed=0` | 数字卡 | `is_completed` |
| M6 | 周期任务完成率 | 周期实例的完成占比（仅已到期） | `SUM(is_completed)/COUNT(*) WHERE source_type='PERIODIC' AND remind_date<=today` | % + 副标题"仅统计已到期实例" | `source_type` |

**实际布局**：**3 行 × 2 列**等高卡（`IntrinsicHeight` + `CrossAxisAlignment.stretch`）：

| 行 | 左 | 右 |
| :-- | :-- | :-- |
| 1 | M1 今日完成率（环形） | M3 连续打卡（暖色高亮 + 里程碑进度条；0 天回落中性灰） |
| 2 | M2 本周完成率（7 格点阵） | M4 逾期任务（0 条绿色正向反馈） |
| 3 | M5 待处理总数 | M6 周期完成率 |

- 连续打卡里程碑：`3 / 7 / 14 / 30 / 60 / 100 / 180 / 365`（`kStreakMilestones`）；
- M4 卡片 **不可点击**（逾期筛选尚未实现，避免半截功能）；
- 统计页默认范围为「本周」。

## 4. 实现注意

1. **一次性聚合**：每个指标一条 SQL，禁止在 Dart 侧遍历全表（万级任务会卡顿）。
2. **并行查询**：`statsSummaryProvider` 用 `Future.wait` 并行 **7 条**查询（M1、M2、M2 点阵、M3、M4、M5、M6）。
3. **日期边界**：`substr` / `strftime` 直接作用于 `YYYY-MM-DD HH:mm:ss` 字符串，格式必须严格一致（见 [02 §2](./02-数据库设计.md)）。
4. **streak**：`SELECT DISTINCT substr(completed_at,1,10) ... ORDER BY d DESC LIMIT 400`，Dart 侧回溯（可单测）。
5. **周期计入**：M1/M2 不区分来源；M6 单列周期（D3）。
6. **空态**：`StatsSummary.isEmpty`（M1/M2/M3/M4/M5/M6 全为 0）→ 展示「还没有统计数据」引导而不是一排 `--`。
   ⚠️ 该判定只看首屏 6 项：若用户只有**历史**完成记录、当前无待办，也会进入空态，但下方图表在「全部」范围下有数据。后续可改为「全库是否有记录」。

## 6. 实施决策（D1~D4）

| 决策 | 结论 |
| :-- | :-- |
| D1 图表库 | **引入 `fl_chart 1.2.0`** 做 A1 折线 / A2 环形 / A3 柱状；A7 热力图自绘 |
| D2 范围作用域 | `今天 / 本周 / 本月 / 全部` 分段控件**只作用于 A1/A2/A3**；M1~M6 固定口径；A7 自带月份翻页（**范围切换不会重置热力月份**，月份独立维护） |
| D3 周期计入口径 | M1/M2 计入全部任务（含周期实例），M6 单列周期口径（仅已到期实例，含孤儿记录） |
| D4 v1 范围 | P0（M1~M6）+ P1（A1/A2/A3/A7）；P2（A4/A5/A6/A8）延后 |

### 6.1 与原始提案的差异

| # | 差异 | 原因 |
| :-- | :-- | :-- |
| 1 | A1 粒度随范围变化（今天=小时、本周/本月=天、全部=月） | 「今天」按天只有一个点，无趋势意义 |
| 2 | A2 统计范围内全部任务（含已完成），而非仅待处理 | 与范围切换语义一致 |
| 3 | M4 逾期卡 v1 不可点击 | 逾期筛选延后（B7） |
| 4 | 图表不画轴刻度（`titlesData.show = false`），用首/中/末标签与图例 | 窄屏可读性；后续可补 y 轴数值 |
| 5 | 首屏 3 行 2 列等高卡（`IntrinsicHeight` + `stretch`） | 直接 `stretch` 在无界高度约束下会触发布局断言（已修） |
| 6 | M3 增加里程碑进度、M4 增加 0 条绿色正向态 | 状态型指标做「情绪化」表达 |

### 6.2 空态与降级

- 首屏 6 项全 0 → 「还没有统计数据」引导（见 §4.6 的局限）；
- 分母为 0 → `--`；
- 范围内无任务 → 各图表卡显示「该范围内暂无数据」；
- 写操作（待办/周期/生成）后三个统计 provider 全部纳入失效矩阵，自动刷新。
