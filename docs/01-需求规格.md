## 2. 术语表

| 术语 | 定义 | 数据落点 |
| :-- | :-- | :-- |
| 常规待办 | 用户手动指定日期的一次性待办 | `tasks.source_type = 'REGULAR'` |
| 周期 | 以天为单位的循环规则：名称 + 起始日 + 周期天数 | `periodic_configs` |
| 周期类型 | `interval_type`（DAY/WEEK/MONTH/YEAR）+ `interval_value`，如"每 2 天""每周""每月" | `periodic_configs.interval_type` / `interval_value` |
| 轮长度 | 一轮包含的天数；DAY/WEEK 固定，MONTH 为 28–31、YEAR 为 365–366 | 由 §4.2 推算 |
| 周期项 | 周期内某一天的**模板**待办（第几天 + 标题 + 提醒时间） | `periodic_items` |
| 周期实例 | 由周期项在某一轮推算出的**真实**待办记录 | `tasks.source_type = 'PERIODIC'` |
| 轮次 | 周期的第几轮，`cycle_index`，0-based | `tasks.cycle_index` |
| 天序 | 周期内第几天，`day_offset`，0-based（0 = 第 1 天） | `periodic_items.day_offset` |
| 待处理 / 已完成 | `is_completed = 0 / 1` 的两个分组 | `tasks.is_completed` |
| 逾期 | 提醒日期早于今天且未完成（实时派生，**不入库**） | 计算得出 |
| 孤儿记录 | 来源周期已被删除、但作为历史保留的已完成周期实例 | `tasks`：`source_type='PERIODIC' AND periodic_id IS NULL` |

## 4. 周期规则（核心算法）

> 业务规则见本节；字段定义与 SQL 见 [02-数据库设计.md](./02-数据库设计.md)；实现细节见 [04-数据层与CRUD.md](./04-数据层与CRUD.md)。

### 4.1 周期类型与预设（Q14 已决策）

| UI 文案 | `interval_type` | `interval_value` | 一轮天数 |
| :-- | :-- | --: | :-- |
| 每天 | DAY | 1 | 1（固定） |
| 每 2 天 / 自定义天数 | DAY | N | N（固定） |
| 每周 | WEEK | 1 | 7（固定） |
| 每 2 周 | WEEK | 2 | 14（固定） |
| 每月 | MONTH | 1 | 28–31（**按自然月**，日号锚定 `start_date`） |
| 每年 | YEAR | 1 | 365–366（**按自然年**） |

不采用"每月 = 30 天"近似：3 个月即漂移 1–2 天，"每月 1 号交房租"会逐步跑到 2 号、3 号。

### 4.2 实例推算

```
cycleStart(k)：                                     // k = 0,1,2,…
  DAY   → start_date + k × interval_value 天
  WEEK  → start_date + k × interval_value × 7 天
  MONTH → start_date 加 (k × interval_value) 个月，日号锚定；目标月无该日号则取该月最后一天
  YEAR  → start_date 加 (k × interval_value) 年，同上（2/29 → 2/28）

cycleLength(k) = cycleStart(k+1) − cycleStart(k)     // MONTH 为 28–31，YEAR 为 365–366
实例提醒日期   = cycleStart(k) + item.day_offset 天
生成前置条件   = is_active = 1 且 (end_date IS NULL OR remind_date <= end_date)
幂等保证       = UNIQUE(periodic_item_id, cycle_index) + ON CONFLICT DO NOTHING
```

⚠️ MONTH/YEAR 的日历算术**必须在 Dart 层实现**：SQLite 的 `date(x,'+1 month')` 对月末溢出是进位而非收敛（实测 `2026-01-31 +1 month = 2026-03-03`）。详见 [02 §7.1](./02-数据库设计.md)。

### 4.3 `day_offset` 约束（Q12 已决策）

- 保存校验：`0 <= day_offset < minCycleLength`（DAY/WEEK 取精确值，**MONTH 取 28，YEAR 取 365**）。
  因此 **MONTH 最大只能选第 28 天（`day_offset = 27`）、YEAR 最大只能选第 365 天（`day_offset = 364`）**。
- 「短月份跳过」在 UI 可达范围内**不会发生**（上限恒小于最短轮长度）；生成引擎仍保留
  `day_offset >= cycleLength(k)` 的防御分支，只对直接写库的历史数据生效。
- 缩短周期导致已有周期项越界时：**阻止保存**，列出冲突项让用户先调整。
- 旧版「MONTH/YEAR 且 `day_offset >= 28` 提示短月份跳过」的横幅已移除（该提示永远不成立）。

### 4.4 示例

**示例 1**：`start_date = 2026-09-25`，每 2 天；项 A `day_offset=0` 喝牛奶 09:00，项 B `day_offset=1` 喝豆浆 09:00。
（一轮一期：实际只生成「当前轮」两条，本轮完成后才生成下一轮。）

| 轮次 | 轮起始日 | 生成实例 |
| :-- | :-- | :-- |
| 0 | 2026-09-25 | 09-25 09:00 喝牛奶　/　09-26 09:00 喝豆浆 |
| 1 | 2026-09-27 | 09-27 09:00 喝牛奶　/　09-28 09:00 喝豆浆 |
| 2 | 2026-09-29 | 09-29 09:00 喝牛奶　/　09-30 09:00 喝豆浆 |

**示例 2**：`start_date = 2026-09-01`，每月；项 A `day_offset=0` 交房租，项 B `day_offset=27` 月末盘点（每月 28 号）。

| 轮次 | 轮起始日 | 轮长度 | 生成实例 |
| :-- | :-- | --: | :-- |
| 0 | 2026-09-01 | 30 | 09-01 交房租　/　09-28 月末盘点 |
| 1 | 2026-10-01 | 31 | 10-01 交房租　/　10-28 月末盘点 |
| 5 | 2027-02-01 | 28 | 02-01 交房租　/　02-28 月末盘点（`27 < 28`，正常生成） |

> 早期版本用 `day_offset=28`（“第 29 天”）演示「2 月跳过」，该值在 Q12 定案后**不可保存**；
> 跳过分支现在只作为防御逻辑保留（见 §4.3）。

### 4.5 删除与完成语义（Q5 / Q9 / Q13 已决策）

| 操作 | 结果 | 统计 |
| :-- | :-- | :-- |
| 标记完成 | 记录保留，`completed_at` 写入 | 计入分母与分子 |
| 取消完成 | `completed_at` 置 NULL；周期实例重算 `completed_count` | 移出分子 |
| 删除单条待办 | **物理删除**（无论是否已完成）；**5 秒内可撤销** | 从分母与分子同时消失 |
| 删除周期项 | 未完成实例删除；**已完成实例保留**并断开关联；**不可撤销** | 已完成记录继续计入历史 |
| 删除周期 | 未完成实例删除；周期项模板级联删除；**已完成实例保留**为孤儿历史记录（保留 `cycle_index` 与周期名快照）；**不可撤销** | 已完成记录继续计入历史 |

三级删除入口（周期实例）：**删这一次**（默认，可 5 秒撤销）/ **删该事项的未来待办**（该实例 + 之后，不可撤销；逾期实例也走同一范围，N22）/ **删整个周期**（不可撤销）。
孤儿历史记录在待办页正常展示为"周期·{快照名}"，不提供跳转周期入口，可取消完成或删除。

### 4.6 其他约定

- 周期实例生成后，用户可单独修改该实例的标题、时间、完成状态，**不回写模板**。
- **规则/日期变更（N14）**：修改 `start_date` / `interval_*`，或修改周期项的 `day_offset` / `remind_time` 后，
  **已完成实例保持原日期不变**；**未完成计划按新规则从「今天所在轮」重建**（`rebuildPending`）。
  周期编辑页/事项编辑页的提示文案与此一致；`completed_count` 不重置。
  （原 Q8「已生成实例一律不变」只对已完成实例成立。）
- 今日进度、待办列表均**包含**周期实例；待办页只展示「当前轮」的未完成实例（一轮一期）。
- 逾期的周期实例：**在本轮窗口内**照常显示为逾期，并阻塞该轮完结判定，需手动完成或删除；
  若**整轮窗口已结束**，当前轮顺延到今天所在轮，旧轮未完成实例保留在库中但**不在待办页展示**
  （日程页可见，统计仍计入）。

### 原文与实际设计的差异说明

| 原文表述 | 实际采纳 | 原因 |
| :-- | :-- | :-- |
| "周期天数（一天、二天、每周、每月、每年）" | `interval_type` + `interval_value`，预设含 每天/每 2 天/每周/每 2 周/每月/每年 | 原文末尾"修改"要求以天数为主的自定义周期；评审又要求补回"周、月"默认项。不用 30 天近似"每月"，MONTH/YEAR 走日历算术（§4.1） |
| "周期开始时间" | `start_date`（仅日期，不含时间） | 提醒时间挂在周期项上，周期本身不需要时间点 |
| "类型（日常、周期）" | `source_type` = `REGULAR` / `PERIODIC` | 原文"日常"统一表述为"常规" |
| "优先级颜色"（单字段） | 拆为 `priority`（枚举）+ `accent_color`（色带） | 一个字段承担两种职责会与 Dart 模型冲突，见 [02 §6 变更 4](./02-数据库设计.md) |
| 周期事项"提醒时间依据周期时间而非具体时间" | 周期项存 `day_offset` + `remind_time`，实例存推算出的 `remind_date` | 原文未定义"周期内第几天"的存储方式，这是 v1 表结构的致命缺口 |
| （原文未涉及）删除周期 | 未完成实例删除，**已完成实例保留为历史记录** | 2026-09-25 评审决策，避免删周期连带抹掉已完成的历史与统计 |
| （原文未涉及）子任务 | **v1 不做**，每条待办都是独立任务 | 2026-09-25 评审决策 |
| "统计页面指标未规划好" | 由 [05-统计指标建议.md](./05-统计指标建议.md) 提供提案 | 原文点名需要参考建议 |
